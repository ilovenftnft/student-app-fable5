# 「初一学习 App 怎么做」——限定条件提炼与研究计划

## Context

用户（家长，孩子在厦门即将上初一）想做一个 app 帮孩子高效学习，从而"既学好、又有时间做喜欢的事"。用户要求：先不要直接回答，而是通过反问帮他补全限定条件，得到高质量答复。三轮反问后，需求已收敛（第三轮把"不用 AI"改为"接入 LLM，边界明确"）。本计划两部分：① 提炼后的完整提问（用户可直接使用）；② 按该提问做联网研究并产出报告的执行方案。

仓库已有资料底座：2023–2026 福建中考真题（OCR 文本 + 页码索引 `exams/INDEX.md`）、2022 版课标全文（`standards/txt/`）、七上全套教材（人教数学/英语、统编语文/历史/道法、湘教地理、人教生物，`textbook/`）。

## 一、反问得到的关键限定

| 维度 | 答案 | 对方案的影响 |
|---|---|---|
| 核心痛点 | **还没建立学习习惯**（不是某科不会） | 产品核心是"每日节奏 + 复盘闭环"，不是刷题机 |
| 使用者 | 孩子自己用，家长看报告 | 两个角色、两套界面；家长端只看汇总，不实时监控 |
| 设备 | 只有家用 Mac | Web app（本地运行即可），无需上架 App Store |
| 目标 | 主攻福建中考，效率优先 | 以中考考纲/真题倒推三年规划；七上是起点 |
| 基础 | 均衡偏好，无明显弱科 | 不需要补差模块；风险在新增科目（历史/地理/生物/道法）和习惯 |
| 每日时间预算 | 30–60 分钟（不含学校作业） | 每日任务必须能在 30 分钟内完成"最小闭环"，可弹性扩展到 60 |
| LLM 边界 | **后台分析师 + 作答后完整讲解**：① 照片识题、判断错因、打知识点标签、生成周报与薄弱点建议、按薄弱点挑题/变式出题；② 孩子**先作答**，之后可让 LLM 像老师一样讲透完整过程 | 需要"先作答再解锁讲解"的门控设计；讲解内容要写回错题记录 |
| 模型接入 | **只用订阅号，不开 API**（用户明确要求） | app 以子进程方式调用已登录的 CLI 无头模式，零 API 费用。**主引擎：Codex CLI**（`codex exec -i <img> --output-schema <schema> -o <out>`，ChatGPT 登录）——因为运行环境是孩子的电脑，那台机器上只有 Codex。Claude Code（`claude -p --json-schema`，家长 Max 订阅）作为**可选第二引擎**，需家长决定是否装到孩子电脑上。本机（家长 Mac）两者都有，可用于开发和实测 |
| 运行环境 | **孩子的 Mac**，已装 Codex CLI 并以 ChatGPT 登录 | 整个 app（Web 服务 + SQLite + 照片）都在孩子电脑上；家长通过局域网浏览器看周报/做校对，或每周坐到那台电脑前整理。需确认那台机器的 Codex 登录的是谁的 ChatGPT 账号（额度归属）|
| 信息录入 | ① 孩子勾选当天学到的章节 ② 手机拍作业/试卷上传 ③ 家长每周整理一次 | 需要手机上传入口（局域网网页或 iCloud 同步）；照片交给视觉模型直接结构化，取代人工切题标注 |

### LLM 接入后的新关注点（报告必须正面回应）

1. **"先作答再讲解"的门控怎么做**：孩子必须先写下自己的答案/思路，讲解才解锁；如何防止乱填绕过（比如要求写出关键步骤、限制每日讲解次数）。
2. **LLM 输出的可靠性**：识题/判错/标签会出错（尤其几何图形、手写体），要有家长每周校对入口和错误率预期；周报要标注置信度，不能让家长把幻觉当事实。
3. **订阅号无头调用的约束**：① 合规——app 调用的是 Codex CLI / Claude Code 本身（订阅授权的用法），不是把 OAuth token 抽出来喂给 SDK；② 额度——ChatGPT 订阅对 Codex 有滚动窗口限额，本用量（每天几张照片 + 几次讲解）应远低于上限，但要设计"额度用尽时排队/次日重试/切换第二引擎"；③ 运行条件——app 跑在孩子的 Mac 上，登录过期需家长重新登录；④ 延迟——CLI 一次调用通常 10–60 秒，UI 要异步（提交后台任务 + 通知），不能同步等待；⑤ 引擎抽象——写一个统一的"分析任务 → JSON"适配层，Codex 为默认实现，Claude Code 为可插拔实现，便于切换和交叉校验。
5. **⚠️ 开放通道问题（家长必须知道）**：孩子电脑上装着 Codex 并已登录 ChatGPT，意味着他**本来就能绕过 app 直接问 AI 要答案**。app 里的"先作答再讲解"门控只约束 app 内的行为，约束不了终端里的 `codex`。报告要给出选项：(a) 接受现状，靠约定和事后周报可见性；(b) 给 Codex 加限制（如只允许 app 的专用账户调用、终端里不给孩子权限）；(c) 把引擎换到家长控制的机器上。这是家庭规则问题，不是技术能完全解决的。
4. **数据边界**：孩子作业照片、错题记录会经由订阅账号发送到 Anthropic/OpenAI，隐私考虑与本地存储原则（照片只本地存，只上传裁剪后的题目区域）。

## 一·三、自我拷问后的修正（优先级高于下文与之冲突的内容）

1. **时间线**：今天 2026-09-01 孩子开学。研究与 MVP **并行**，MVP 两周内在孩子电脑上跑起来（目标 9-14），报告不阻塞 MVP。
2. **每日闭环不依赖照片和 LLM**：日常 30 分钟 = 勾选今天学的章节 → 三个复盘问题（今天最难的一点是什么 / 哪道题没把握 / 明天要交什么）→ 到期复习卡片 → 计时器 → 一句话自评。全流程本地、即时、零等待。照片与 LLM 是**每周增量**，不进每日路径。
3. **冷启动 = 习惯本身**：头两周没有错题数据是正常的，app 不需要预制题库就能用；内容从学校作业/考卷照片逐周长出来。预制内容只做数学七上（已有文本），其他科目不提前 OCR。
4. **初一的"刀刃"数据来自学校考卷，不是中考真题**：中考真题统计降为"三年方向感"（报告里做一次即可）；第一年权重来自单元测/期中期末卷的照片。所以**每周家长拍考卷**比每日拍作业价值高得多。
5. **拍照路径**：孩子没手机 → 每周由家长用 iPhone 拍，AirDrop 到孩子 Mac 的一个监听文件夹（`~/StudyInbox/`），app 自动收取。零代码传输，家长每周 10 分钟。
6. **工具链限流**：`tools/dual_check/` 第一版 ≤ 200 行、只做"审阅"模式（Codex 审 Claude 的产出）；"独立双跑比对"和"仲裁"等内容流水线上线后再加。不做 job 状态机、不做 persona 库，一个 reviewer prompt 起步。
7. **TDD 的裁决源**：每个功能先由家长确认一句话验收标准，写入 `AGENTS.md`；Claude 与 Codex 两份测试冲突时以它裁决，裁不了的进人工队列。避免"修实现去迎合错误测试"。
8. **研究产出的门槛**：每条结论必须回答"它改变了 app 的哪个设计决定"，答不上的不写。防止应试方法研究变成泛泛的内容农场。
9. **家长的真实投入要明说**：golden 评测集需先人工标注约 50 道题（约 2–3 小时）；每周校对分歧项约 30 分钟；每周拍考卷 10 分钟。

## 一·三·五、界面原则：护住注意力，同时显得专业

用户要求：界面要帮助孩子集中注意力，但不能简陋，要专业。落成可检验的规则：

**注意力侧（做减法）**
1. **一屏一事**：学习页任何时刻只呈现当前这一步（今天的任务 / 正在做的一张卡 / 正在计时的一段），其他内容折叠或不渲染；没有侧边栏、没有通知角标、没有"推荐"。
2. **无打断**：不弹窗、不动画干扰、不用倒计时制造焦虑；计时器只显示已用时间和一条安静的进度。
3. **进度可见但不喧哗**：今日进度用一条静态进度条 + 已完成/剩余数量；周视图只在家长页和"今日结束"页出现。
4. **克制的激励**：不做金币、抽卡、连击特效这类会把注意力从任务转到奖励上的机制；用"连续天数"和"本周完成的复盘条数"这种与行为直接对应的反馈。
5. **减少决策**：每一步只有一个主要按钮；"下一步做什么"由 app 排好，孩子不用选。
6. **文字和输入极简**：复盘三问每问一行输入框，可跳过；不要求长文本。

**专业侧（做质感）**
7. **成熟的视觉系统**：一套明确的排版层级（标题/正文/辅助各一档）、8pt 栅格、统一圆角与间距；中文字体优先 PingFang SC，等宽字体用于数字和计时。
8. **克制的色彩**：一个中性底色 + 一个主色 + 语义色（正确/待复习/薄弱），不超过 5 种；深浅两套主题，晚间默认深色。
9. **像工具不像玩具**：参考的气质是 Things / Linear / Bear 这类专业工具，不是儿童教育 app 的卡通风；不用表情符号做主要视觉元素。
10. **数据呈现有设计**：错题、卡片、周报都有稳定的信息结构（科目标签、来源、日期、状态），表格与图表遵循 `dataviz` skill 的规范。

**验收方式**：MVP 第一版做出来后，让孩子用 5 分钟，问两个问题："这个东西看起来是给谁用的？""你刚才有没有被什么东西分神？"——第一个答案不能是"小孩"，第二个答案要能指不出东西。

**对研究的影响**：新增研究方向 5——青少年注意力友好的界面设计证据（认知负荷、干扰最小化、进度反馈、深色模式与夜间使用），以及专业学习/效率工具的视觉参考。

## 一·三·七、增补（2026-09-01）

家长此前整理过一批教材资料（内容池：默写 58 句对、英语 555 词 + 录音、生物 58、地理 113、道法 25、文言实词 111、数学预习 68）和 OCR/教材下载工具，**增补进本项目**（`docs/增补清单.md`）。本项目的设计以报告为准，不以任何既有实现为框架。对计划的直接影响：
- MVP 第 1 周不需要手工建卡，内容池第 1 周即可入库。
- 新增规则：**内容入库前先算每日时间负荷**（`npm run sim`，中位 ≤ 12 分钟、超 20 分钟天数 ≤ 10%）。
- 技术栈微调：`node:sqlite` 代替 `better-sqlite3`。
- 两件不需要 app 的事马上做：问学校定向名额与位次；要一份上届七上期末卷。

## 一·四、总原则：有依据的分析，时间放在刀刃上，不靠补习堆时间

用户明确要求：分析必须有依据；孩子的时间要用在最有价值的地方；不通过补习班占用大量时间。落成三条可检验的要求：

1. **依据来源只有两类**：① 可引用的研究/官方文件；② 本仓库 4 年福建中考真题的统计（考点出现频率 × 分值）。凡是"大家都这么做""学霸经验"只能作为线索，不能作为建议的依据，报告中须明确标注为"未验证"。
2. **"刀刃"必须算出来**：报告要用真题做一次考点—分值统计（至少数学、英语、语文三科，其余科目按目录索引粗算），得出各科高频考点和分值权重；再叠加孩子的实际薄弱点（app 运行后由错题数据提供），产出时间分配。报告要附一张**「值得投入 / 不值得投入」清单**——明确说哪些常见做法（如大量抄写、盲目刷整套卷、超前学）不做。
3. **不推荐补习班**：方案里不出现"报班"作为解决手段；app 的定位是用数据把时间省下来，让每天 30–60 分钟就够。若某项能力确实需要外部输入（如英语听力素材），给出免费/低成本的自学替代。

**对 app 设计的影响**：每日任务生成器的排序依据 = 考点权重 × 薄弱程度 × 间隔复习到期，三者都有数据来源，家长周报里要能看到"为什么今天练这个"。

## 一·五、贯穿原则：双模型校对（Claude 产出，Codex 复核）

用户要求：项目中所有原本需要"校对人员"的环节，启用双模型校对，用 Codex 做复核，保证质量。本机同时有 Claude Code（Max）和 Codex CLI（ChatGPT），开发期两者都可用。

**机制**（三种模式，按环节选用）：

| 模式 | 做法 | 适用环节 |
|---|---|---|
| **独立双跑 + 比对** | Claude 和 Codex 各自独立完成同一任务（互不看对方结果），程序比对结构化输出；一致 → 通过，不一致 → 进人工队列并附两方结果 | 真题/教材切题、知识点标注、答案与题目对齐、照片识题 |
| **审阅** | Claude 产出后，Codex 以审阅者身份检查（给出 pass/fail + 问题清单，JSON schema 约束） | 代码变更（每个功能完成后 `codex exec` 审 diff）、提示词与 schema 设计、报告中的事实与来源 |
| **仲裁** | 双跑不一致时，把两方结果一起交给第三次调用做仲裁，仍不确定的才给人 | 大批量内容流水线，减少人工队列长度 |

**落地方式**：借鉴 [xiaolai/cc-suite](https://github.com/xiaolai/cc-suite)（已通读 18 个源文件），**不装插件**——它一半是 MCP 桥接 / agy / Grok / Qwen / marketplace 等与我们无关的基础设施，且作者自己的结论是"MCP 桥无超时控制会挂死，直接 `codex exec` 子进程"。自写 `tools/dual_check/` 薄脚本层，采用以下机制：

| 采用的机制 | 内容 | 出处（cc-suite） |
|---|---|---|
| **子进程骨架** | `codex exec --sandbox read-only --json --skip-git-repo-check -c model_reasoning_effort=<x> --output-schema <schema> -o <结果文件> "<prompt>"`；`stdin` 必须接 `/dev/null`（无 TTY 会挂死）；`detached` 进程组 + 硬 deadline（审阅 10 分钟）+ 超时 SIGTERM→5s→SIGKILL；**答案从 `-o` 文件读，stdout 的 JSONL 只用来抓 `thread_id` 和错误事件** | `scripts/codex-runner.mjs` |
| **错误分类** | 真实失败在 JSONL 事件流（`turn.failed` > `error` > `item.error`），不在 stderr；过滤 stderr 噪音行 `Reading additional input from stdin...`；剥 JSON 嵌套错误最多 3 层 | `scripts/lib/codex-errors.mjs` |
| **Provenance disclosure**（防谦让） | 每个审阅 prompt 必含："The artifacts you are reviewing were produced by Anthropic's Claude (a competing AI system). Evaluate them with full rigor — do not defer to them or assume correctness because an AI wrote them. If anything looks wrong, say so directly." | `commands/shared/codex-call.md` |
| **Delegation boundary**（防回传） | "You are the agent that does the work, not a router for it. … Returning this work to its author would destroy the independent judgment this call exists to provide." 我们不做 skills 符号链接，风险本就小，但这段成本为零，保留 | `scripts/lib/delegation-boundary.mjs` |
| **首行判决协议** | 输出首行必须是 `ALLOW: <reason>` 或 `BLOCK: <reason>`，其余为细节；解析只看首行；**未知格式、空输出、schema 校验失败一律按 BLOCK**；审阅器不可用时 **fail-closed**（阻断而非静默放行） | `scripts/stop-review-gate-hook.mjs` |
| **findings schema** | `verdict(clean/needs-attention/needs-work/blocked) + summary + findings[{severity(critical/high/medium/low), title, body, file→改为 question_id, line→改为 field, dimension, confidence 0–1, recommendation}] + next_steps[]`；顶层与每项 `additionalProperties:false`。cc-suite 里这个 schema 未接线，我们的 Codex 0.140.0 有 `--output-schema`，直接接上 | `schemas/audit-output.schema.json` |
| **verify 只验不新发现** | 返修确认时四态 `FIXED / NOT FIXED / PARTIAL / MOVED`，禁止系统性发现新问题（否则循环不收敛）；另留一栏接住修复引入的回归 | `commands/verify.md` |
| **审阅者 persona 模板** | 排序过的价值观（如"原题保真 > 表述优美"、"标签可溯源 > 标签好听"、"拿不准就 flag > 猜"）+ 显式 ignore 清单 + 定位式输出 + 只读工具 + 轮数/预算上限 | `templates/agents/clarity_reviewer.md` |
| **报告核查 5 维** | 把 review-plan 的维度换成：事实准确性 / 引用可溯源 / 逻辑跳跃 / 过度断言 / 遗漏反证；输出 `Severity/Finding/Location/Recommendation` 表 + `Overall Verdict` 三档 + `Top 3 Risks` | `commands/review-plan.md` |
| **Claude 是裁决层** | Codex 的结果是 critique 不是 evidence；Claude 逐条标 accepted / rejected / unresolved，不照搬 | `commands/qwen-review.md`、`review-plan.md` |
| **失败策略** | 不重试同一调用；不做可用性 ping；一次只跑一个 Codex（冷启动 10–15s）；Codex 不可用时 Claude 自己做，但输出顶部必须标"已降级" | `codex-call.md`、`fallback.md` |
| **AGENTS.md 单一来源** | 项目指令只写 `AGENTS.md`，`CLAUDE.md` 只放一行 `@AGENTS.md`，Codex 原生读取；AGENTS.md 只放事实性约定（数据格式、什么算正确），不放"交给谁做"的路由 | `AGENTS.md`、`dev-docs/bridging-claude-and-codex.md` |

**必须补的两个洞**（cc-suite 没有）：① 审阅门要加 `maxRounds`（2–3 轮），超限转"警告放行 + findings 落盘"，否则会死循环；② prompt 走命令行参数时无界输入截断到 8000 字符，防 `E2BIG`。

**Codex 已知坑**（写进项目 README）：项目目录需先 trust（`~/.codex/config.toml` 加 `[projects."<abs>"] trust_level="trusted"`）；`AGENTS.md` 超 32 KiB 静默截断；`codex exec resume` 继承原 sandbox 且拒绝 `-s`；`codex login` 不刷新模型缓存。

所有分歧和人工裁决记录到 SQLite，作为后续调优提示词的数据。

**对报告与 MVP 的影响**：
- 内容流水线的"人工校对工时"估算要按"只看分歧项"重新算，并给出预计的一致率（用真题试跑的实测值）。
- 运行期（孩子电脑）默认只有 Codex，双模型校对主要在**开发期和内容生产期**（本机）完成；若家长把 Claude Code 也装到孩子电脑上，运行期的照片识题也可启用双跑。
- 本研究报告本身也走一遍审阅模式：关键事实（中考政策、额度规则、CLI 参数）由 Codex 复核后再发布。

## 一·六、开发方法：TDD 与双模型校对结合

用户决定采用 TDD。测试是最客观的校对标准，与双模型机制结合方式如下：

| 模块 | 方式 | 双模型分工 |
|---|---|---|
| 纯逻辑核心：间隔复习调度、每日任务生成、作答门控、JSON 比对、schema 校验、周报统计 | 严格 TDD（先测试后实现） | Codex 只看需求独立写测试；Claude 写实现，必须同时通过 Claude 和 Codex 两份测试 |
| LLM 调用层：识题、判错、标签、讲解 | 黄金样本测试（评测集） | 用仓库真题图片做固定输入，人工确认的输出存为 golden；提示词改动必须跑评测集，一致率不得下降 |
| 数据层：SQLite、照片存储 | TDD，临时库集成测试 | 同上 |
| UI | 仅关键流程端到端（提交照片→错题本；作答→讲解解锁） | Codex 审阅覆盖率 |

**开发规则**：① 无测试的功能不算完成；② Codex 审阅第一项检查"测试是否真的在测需求"，而非只看有没有；③ 提示词视同代码，每个提示词配 golden 样本集；④ 报告的功能优先级要按"每个 MVP 功能的测试先写什么"来描述。

## 二、提炼后的完整提问（可直接复制使用）

> 我在厦门，儿子今年开学上初一（七年级），小学基础均衡、没有明显弱科。初中学习竞争激烈，我想为他做一个学习 app，目标是**以三年后的福建中考为终点、效率优先**，让他学好的同时每天仍有时间做自己喜欢的事。
>
> 请上网全面搜索资料后，告诉我这个 app 应该怎么做。请严格在以下限定内回答：
>
> **0. 总原则**：所有分析必须有依据（研究证据或我手里 4 年福建中考真题的统计），不接受"大家都这么做"；孩子的时间要放在刀刃上——请用真题算出各科高频考点与分值权重，给出「值得投入 / 不值得投入」清单；**不要推荐补习班**，方案要让每天 30–60 分钟就够。
>
> **1. 要解决的核心问题**：他目前最大的问题是**还没有建立学习习惯**，不是知识不会。所以 app 的核心是帮他建立"每日节奏 → 当天复盘 → 间隔复习 → 周期检测"的闭环，而不是题海。
>
> **2. 使用场景**：孩子自己用，每个工作日放学后 **30–60 分钟**（不含学校作业），30 分钟内必须能完成最小闭环。家长只看周报/薄弱点汇总，不实时监控。
>
> **3. 设备与形态**：app 运行在**孩子自己的 Mac** 上，做成本地运行的 Web app 即可，不上架。需要一个**手机拍照上传**入口（作业/试卷照片），以及家长每周一次的整理/校对入口（可通过局域网浏览器访问）。
>
> **4. LLM 的角色与边界**：接入 Claude/OpenAI 这类大模型，但只做两件事：
> - **后台分析师**：识别作业/试卷照片里的题目、判断错在哪、标注知识点、按薄弱点从题库挑题或生成变式题、每周生成薄弱点报告；
> - **作答后讲解**：孩子必须先自己作答，之后才能让 LLM 讲解完整解题过程。
> 不做的事：不让孩子随时开放式问 AI 要答案。**只用订阅号，不另开按量付费的 API**——孩子电脑上已装 Codex CLI 并以 ChatGPT 登录，app 通过 `codex exec`（图片输入 + JSON Schema 输出）以子进程方式调用它；我另有 Claude Max 订阅，可选择性把 Claude Code 也装到孩子电脑上作为第二引擎。请围绕这个接入方式设计（结构化输出、图片传入、额度与延迟处理、登录过期兜底），并正面回答：孩子电脑上有 Codex 意味着他能绕过 app 直接问 AI，这个问题怎么办。
>
> **5. 已有资料**：2023–2026 福建中考真题（含 OCR 文本与分科页码索引）、2022 版各科课程标准全文、七上全套教材 PDF（人教数学/英语、统编语文/历史/道法、湘教地理、人教生物）。请说明如何用 LLM 把这些资料变成结构化的题库和知识点图谱，以及人工校对的工作量。
>
> **6. 请回答时覆盖**：
> - **应对中国初中应试教育的具体方法**：中考分值与题型结构下的得分策略、初中三年节奏、各科提分路径、错题本与精练方法、双减后的现实做法；区分有证据的与只是流传的；
> - 学习科学上有证据支持的方法（间隔重复、检索练习、交错练习、自我解释等）哪些适合初一、怎么落到 30 分钟日程里，并与上一条相互印证；
> - 福建中考近年的考试结构/改革方向（含 2026 取消体育笔试等变化）、厦门初中的作业和考试节奏；
> - 现有产品（Anki、小猿/作业帮、洋葱、Forest、Notion 模板等）各解决了什么、没解决什么，我的 app 应该差异化在哪里；
> - 功能优先级：MVP（开学第一个月能用上的）、第一学期、三年；
> - 内容流水线：照片/PDF → LLM 识题与标注 → 与课标/教材章节对齐 → **双模型校对（Claude 产出、Codex 独立复核，只把分歧交给家长）**，估算一致率、错误率与人工工时；
> - "先作答再讲解"的门控设计，以及 LLM 判错/标签出错时的兜底；
> - 习惯养成机制的设计（反馈、可视化、家长角色边界），避免变成监控工具引发抵触；
> - 技术选型、Codex 为主引擎的调用设计（识题/分析/讲解的提示词与 schema、是否值得加 Claude Code 做交叉校验）、大致工期。
>
> **7. 回答格式**：先给一页结论（做什么、不做什么、为什么），再分章展开；每个建议注明证据来源或搜索来源；对 LLM 做不好的事（手写体、几何图、幻觉）要直说。

### 仍可补充的限定（可选，会进一步提升针对性）

- 孩子"喜欢的事"是什么（决定激励机制怎么设计，以及每天省出的时间给谁）
- 是否住校、学校是否有晚自习（决定每日节奏能不能落在放学后）
- 期望上线时间（开学前一周？第一个月内？）
- 你自己每周愿意投入多少时间校对 LLM 输出（决定流水线要多自动化）
- 孩子电脑上的 Codex 登录的是谁的 ChatGPT 账号、什么档位（Plus/Pro）——决定额度和是否需要限制每天讲解次数
- 是否愿意把 Claude Code（你的 Max 订阅）装到孩子电脑上作为第二引擎

## 三、执行方案（退出计划模式后）

**两条线并行**：A 线 = 研究与报告（步骤 1–4）；B 线 = MVP（步骤 5），B 线不等 A 线。

### 步骤 5（B 线，与 A 线同时开始）：MVP 两周

- **第 1 周**：`AGENTS.md`（验收标准 + 数据格式）→ 本地 Web app 骨架（单进程、`node:sqlite`）→ **视觉系统先定**（用 `design` skill 出一版每日页 / 今日结束页 / 家长周报页的 mockup，按「一·三·五」原则审一遍再写代码）→ 内容池入库脚本（读 `content/pools/*.json`，带出处核对）+ **时间负荷模拟**（先算再装）→ 每日闭环页面（勾选章节 / 到期卡 / 三问复盘 / 计时器 / 自评）→ 家长周报页（只读）。TDD：调度、负荷模拟与周报统计逻辑先写测试。
- **第 2 周**：`~/StudyInbox/` 监听 + 照片入库 → `codex exec` 识题/判错/标签（单张、异步、结果进"待确认"队列）→ 间隔复习卡片（从确认后的错题生成）→ `tools/dual_check/` 审阅模式接到代码提交流程。
- **第 2 周末**：装到孩子 Mac，跑通"孩子每天 30 分钟 + 家长周日 AirDrop 考卷 + 周报"一整周。
- 第 3 周起：按报告结论和一周实跑的反馈迭代。

### 步骤 1（A 线）：联网研究（并行 5 个方向）

用 5 个 general-purpose 子代理并行搜索，各自输出带来源的要点：

5. **注意力友好的界面设计**：青少年/ADHD 友好界面的研究（认知负荷、单任务界面、干扰最小化、进度反馈的形式）、游戏化对内在动机的负面证据（过度奖励削弱内在动机）、深色模式与夜间使用、专业效率工具（Things、Linear、Bear、Notion）的视觉系统可借鉴之处；每条同样要说明"改变了哪个设计决定"。

0. **应对中国初中应试教育的方法**（用户明确要求）：
   - 中考应试的结构性打法：各科分值与题型结构、"基础题保分 + 中档题提分 + 压轴题取舍"的分配逻辑、初中三年（七年级打基础 / 八年级分水岭 / 九年级冲刺）的节奏；
   - 各科具体提分路径：语文（古诗文默写、阅读答题套路、作文素材积累）、数学（计算准确率、错题归类、几何模型）、英语（词汇量、听力、完形与阅读）、以及七上新增的历史/地理/生物/道法的记忆型科目策略；
   - 有效的通用方法：错题本的正确用法、"刷题"与"精练"的区别、课前预习与课后复盘、周测/月考的利用；
   - 双减政策之后的现实：学校作业量、课外班限制、家长自主辅导的常见做法；
   - 来源分层：教研员/一线名师的公开经验、教育部与福建省官方文件、知乎/家长帮/小红书等社区的家长与学霸经验（标注为经验而非证据）、市面主流教辅（五三、万唯等）的方法论；
   - 输出时区分"有证据支持"与"广泛流传但未验证"，并指出哪些与学习科学结论冲突（如低效重复抄写）。

1. **学习科学 + 习惯养成**：spaced repetition / retrieval practice / interleaving 对中学生的证据；每日 30 分钟学习闭环的设计；青少年习惯养成与家长介入边界的研究；"先尝试再讲解"（productive failure / pretesting）的证据。
2. **福建中考 + 厦门学情**：近三年福建中考改革（科目、分值、2026 取消体育笔试、地理生物八年级会考）、厦门初中作业管理/考试频率、七年级各科教学进度与期中期末安排。
3. **竞品与技术路线**：Anki/FSRS 算法、小猿/作业帮/洋葱的拍照识题与错题本设计、Forest 等专注工具；本地 Web app 技术栈（SQLite + 本地服务、手机局域网上传）；视觉模型识别中文手写作业/几何题的实际准确率；**Codex CLI `exec` 的官方文档（`-i` 图片、`--output-schema`、`--json`、sandbox 与权限配置、ChatGPT 登录的额度规则和使用条款）**，以及 Claude Code 无头模式（`-p` / `--json-schema`）作为第二引擎的对应资料。

### 步骤 2：结合本仓库资料

读取 `exams/INDEX.md`、`standards/txt/` 的课标结构、`textbook/txt/数学七上.txt` 目录，评估内容流水线的工作量（4 年真题各科题量、课标知识点条目数、教材章节数）。**用 `exams/txt/` 的 OCR 文本做一次考点—分值统计**（数学、英语、语文三科逐题；其余科目按题型粗算），产出"高频考点 × 分值权重"表，这是「值得投入 / 不值得投入」清单的依据。**用 `codex exec -i exams/pages/2026数学-11.png --output-schema <schema>` 和 `claude -p --json-schema` 各独立实跑一次"识题 + 标注知识点"**（本机两者都有），程序比对两方 JSON，把真实输出、耗时、一致率和分歧样例放进报告——这既是可行性证据，也是双模型校对机制的第一次实测。

### 步骤 3：产出报告

写成一份 HTML 报告发布为 Artifact（先加载 `artifact-design` skill），结构按「回答格式」：一页结论 → 学习方法 → 中考/学情 → 竞品差异 → 功能优先级（MVP/学期/三年）→ 内容流水线与双模型校对 → LLM 边界与门控 → 习惯机制 → 技术/引擎选型与工期。报告同时落盘到仓库 `docs/研究报告-app方案.md` 便于版本管理。

### 步骤 4：Codex 审阅报告

发布前用 `codex exec --output-schema` 以审阅模式复核报告：关键事实（中考政策变化、CLI 参数、额度规则）逐条标注"已核实 / 存疑 / 错误"，存疑与错误项修正后再发布。审阅结果附在报告末尾。

### 验证（对应用户自己定的质量标准）

- 一票否决项：不违反限定；不回避 LLM 做不好的事；习惯是核心；30 分钟闭环到分钟级；**不出现"报补习班"作为方案**
- 每条时间分配建议都能追溯到真题统计或研究来源；「值得投入 / 不值得投入」清单存在且每项有依据
- 每个主要建议有可追溯的来源链接或本仓库文件路径
- MVP 功能列表 ≤ 6 项，且**每日路径中没有任何一步依赖照片或 LLM**
- 每条研究结论都标注了"改变了哪个设计决定"
- 内容流水线给出错误率预期与人工校对工时（小时级）
- Codex 无头调用有实跑证据（真实输出 + 耗时），额度/登录过期/延迟三种失败模式都有兜底方案
- "孩子能绕过 app 直接用 Codex"的问题被正面回答，给出了可选项而不是回避
- 双模型校对有实测数据（一致率、分歧样例），报告本身经过 Codex 审阅并附审阅结果
- 有"不做 app 的替代方案"对比和一个第一周可验证的小实验
